# V0.3 Evidence Runner Exit Design

**Status:** approved

**Date:** 2026-08-11

**Governing design:** `plan/2026-08-04-环境经济学与政策研究操作系统-设计规范.md`

## 1. Objective

Close V0.3 with one useful, end-to-end Evidence Runner rather than a sequence of
method-specific infrastructure projects. The runner must execute every Wave-1
method family on bounded local data, register diagnostics and results, rebuild a
blinded expected result within declared tolerances, and detect every registered
assumption or integrity failure.

The first complete version favors breadth and a real exit evaluation. Deeper
method variants, additional published replication archives, and performance
hardening follow V0.3.0 instead of blocking it.

## 2. Delivery strategy

Use a hybrid authoritative pack:

1. repository-owned fixtures remain the fast offline CI layer;
2. authoritative external method packages provide independent numerical oracles;
3. official package example data or a small official public snapshot supplies
   scientific exit cases without executing arbitrary author scripts;
4. the existing trusted-local generated-script kernel remains the only executor;
5. a separate blinded evaluator holds expected values and failure expectations.

The runner does not revive the unfinished arbitrary replication-container path.
No downloaded author shell, R, Stata, or Python script is executed in V0.3.0.

## 3. Authority selection

GitHub stars are a soft maintenance signal, not a hard scientific gate. A package
is admissible when its authority record binds all of the following:

- method family and supported estimand;
- official repository or CRAN source URL;
- exact source archive or Git commit SHA-256;
- exact installed version and installed-tree digest;
- license identifier and license URL;
- methodological reference and citation-count snapshot source/date;
- test/example dataset provenance;
- required R version and dependency inventory;
- expected functions, outputs, and comparison tolerances.

The initial authority candidates are:

| Family | External oracle | Initial benchmark |
|---|---|---|
| DiD/event study | `did` | package `mpdta` example |
| RDD | `rdrobust` | package Senate example |
| Synthetic control | `synthdid` | package California Prop 99 example |
| Meta-analysis | `metafor` | package BCG example |
| RCT | `estimatr` plus analytic difference-in-means | owned randomized fixture |
| IV/2SLS and Panel FE | existing `fixest` | owned exact-design fixtures |
| Environmental measurement | Research OS contract | small official EPA AQS snapshot |

An unavailable or license-ambiguous candidate is recorded as rejected and
replaced by an analytically checkable owned case. It is never silently fetched
from an unofficial mirror.

## 4. Managed external acquisition

External downloads are allowed only through a new immutable method-authority
intake, separate from method execution.

1. Resolve official metadata and license.
2. Download the exact source archive or official data snapshot once.
3. Hash and inventory the bytes before installation or parsing.
4. Install R packages into a run-root-scoped managed R library; never mutate the
   system or default user library.
5. Hash the installed package tree and persist its dependency inventory.
6. Generate an immutable `MethodAuthority` record.
7. Execute only repository-generated scripts with the exact managed library.

Retries reuse the content-addressed archive. Several methods may share one
managed library and one data snapshot. Method packs never own datasets.

## 5. Remaining Wave-1 method packs

### 5.1 RCT

The V0.3.0 RCT pack supports individually randomized, two-arm intent-to-treat
analysis with an unadjusted difference in means and a predeclared ANCOVA estimate.
It reports allocation counts, attrition by arm, baseline balance, robust standard
errors, confidence intervals, and the declared primary outcome. Cluster-randomized
designs, treatment noncompliance, and treatment-effect heterogeneity are explicit
post-V0.3 extensions.

The pack blocks PASSED when assignment is non-binary, arms lack support, outcome
missingness exceeds the declared threshold, treatment is deterministically
predictable from baseline fields, or the registered primary outcome is absent.

### 5.2 Synthetic control

The V0.3.0 pack supports one treated unit, one intervention date, balanced unit-
time outcomes, non-negative donor weights summing to one, and no treated donor.
It reports donor weights, pre-treatment RMSPE, post/pre RMSPE ratio, treatment
gaps, in-space placebo distribution, and leave-one-donor-out sensitivity.

The authoritative comparison uses `synthdid`; the Research OS result remains a
typed method artifact rather than a serialized third-party object. Missing donor
support, poor pre-fit above the declared threshold, non-convex weights, or an
unstable leave-one-out result blocks PASSED.

### 5.3 Descriptive environmental measurement

This pack makes no causal claim. It validates measurement unit, timestamp,
location or monitor identifier, detection-limit flags, missingness, duplicates,
and aggregation authority. It reports completeness, quantiles, exceedance counts,
temporal aggregation, monitor coverage, and deterministic figures.

The exit benchmark uses a small immutable EPA AQS snapshot obtained from an
official endpoint. Unit mismatch, duplicate measurement keys, impossible values,
undeclared below-detection handling, or missingness above the declared threshold
is a scientific failure.

### 5.4 Systematic review and meta-analysis

The V0.3.0 pack accepts precomputed independent effect estimates and sampling
variances. It reports fixed-effect and DerSimonian-Laird random-effects estimates,
Q, I-squared, tau-squared, prediction interval, study weights, funnel/forest data,
and leave-one-out influence.

`metafor` is the numerical oracle. Dependent effects, multilevel models, network
meta-analysis, and publication-bias correction are post-V0.3 extensions. Invalid
variances, duplicate study-effect keys, excessive influence, or an unavailable
declared model blocks PASSED.

## 6. Shared contracts and result registry

The existing strict `AnalysisSpec` union gains four method-specific authorities.
All Wave-1 methods continue through the same snapshot, generated-script, exact
runtime, artifact-store, recovery, CLI, and independent-verifier boundaries.

Each method must declare:

- estimand and permitted interpretation;
- required data shape and column roles;
- assumptions and mandatory diagnostics;
- primary estimator and registered sensitivity procedures;
- required tables, figures, and scalar metrics;
- failure thresholds;
- package authority and compatibility version.

Every run publishes immutable snapshot, script, runtime/library authority, raw
outputs, diagnostics, figures, typed result, verification report, and current/
history references. No boolean supplied by a caller is authoritative.

## 7. Blinded V0.3 exit corpus

The exit corpus has two physically separate projections:

- **runner projection:** case manifest, method spec, input snapshot, package
  authority, and output schema;
- **evaluator projection:** expected metrics, tolerances, expected failure code,
  and sealed expected-result digest.

The runner cannot read evaluator files. The evaluator receives only immutable run
references and independently reopens their complete evidence chain.

The first corpus contains:

- one green case for each of the seven Wave-1 families;
- one auxiliary Panel FE green case for shared regression coverage;
- one assumption-failure case per Wave-1 family;
- one cross-method integrity-tampering case.

Green expected values come from analytically checkable fixtures or an admitted
external oracle and are frozen before the tested runner executes.

## 8. Tolerances and comparisons

Every expected numeric leaf declares finite non-negative absolute and relative
tolerances. A value matches only when:

```text
abs(actual - expected) <= atol + rtol * abs(expected)
```

Schemas, term names, method IDs, diagnostics, failure codes, references, hashes,
and figure manifests compare exactly. NaN and infinity never match. Unexpected or
missing outputs are failures. The evaluator records the exact JSONPath or CSV
cell for every mismatch.

## 9. Exit decision

V0.3 closes only when one immutable `V03ExitReport` proves all of the following:

1. all eight green cases reconstruct every registered output within tolerance;
2. all seven assumption-failure cases return their predeclared failure code;
3. the integrity case is rejected before a green result can be consumed;
4. every artifact and package/data authority resolves through current immutable
   history with no unresolved verification finding;
5. restart of an interrupted exit evaluation resumes without duplicate execution;
6. V0.2 planning-only and blind-design boundaries remain unchanged;
7. independent review reports no Critical or Important finding.

The exit report is all-or-nothing. Partial family success cannot be represented as
V0.3 completion.

## 10. Fast-path boundaries

To reach a useful complete version quickly, V0.3.0 deliberately excludes:

- arbitrary published author-code execution;
- one full replication archive for every method;
- fuzzy or geographic RDD, cluster RCT, noncompliance LATE, generalized synthetic
  control, dependent-effect meta-analysis, and advanced exposure modeling;
- automatic prose, paper drafting, or policy interpretation;
- broad performance optimization beyond bounded resources and resumable state.

These exclusions may be added after the formal exit report. They cannot weaken
the evidence, failure, tolerance, or lineage rules above.

## 11. Acceptance tests

Implementation uses RED-GREEN-REFACTOR and shared tasks rather than four parallel
infrastructure projects. Acceptance requires:

- strict contract/data-shape tests for all four new methods;
- renderer/parser and real-managed-R oracle tests;
- all registered diagnostic failures reproduced RED then GREEN;
- tamper, stale-reference, missing-output, and restart recovery tests;
- runner/evaluator projection leakage tests;
- exact tolerance-boundary tests;
- a complete blinded exit run producing `V03ExitReport(status="passed")`;
- unchanged existing econometrics, replication, V0.2, and blind-benchmark tests;
- Ruff, format, strict mypy, lockfile, diff, dependency/license, and changed-file
  line gates;
- independent final review with no Critical or Important findings.
