# V0.3-B Shared Causal-Policy Bundle Design

**Status:** approved approach; written-spec review pending

**Date:** 2026-08-11

**Governing design:** `plan/2026-08-04-环境经济学与政策研究操作系统-设计规范.md`

## 1. Objective

Deliver Panel FE, IV/2SLS, and local-linear RDD together as one useful local-data
bundle. The bundle reuses the trusted CSV snapshot, reviewed local R runtime,
artifact store, verification, recovery, CLI, and reporting chain already used by
the DiD release. It does not create three infrastructure projects and does not
download method-specific data or software.

The release is useful when a researcher can submit an explicit local YAML spec,
run one of the three methods with the already-reviewed `fixest` dependency, and
receive typed estimates, diagnostics, figures, logs, and a re-verifiable report.

## 2. Scope and non-goals

### Included

- two-way or declared multi-way Panel FE with clustered inference;
- IV/2SLS with first stage, reduced form, structural estimate, and instrument
  diagnostics;
- sharp local-linear RDD with a declared cutoff, triangular weights, declared
  bandwidth, bandwidth sensitivity, donut sensitivity, and covariate continuity;
- method-specific schemas and outputs behind one shared recipe registry;
- exact-reference `validate`, `run`, and `status` through the existing CLI;
- repository-owned synthetic fixtures and optional real-local-R smoke tests.

### Excluded

- automatic method selection based on statistical significance;
- automatic data discovery, download, installation, or mutation;
- fuzzy RDD, geographic RDD, regression kink, dynamic panel GMM, or structural
  models;
- claiming that the local-linear RDD is equivalent to `rdrobust` robust
  bias-corrected inference;
- external replication packages, Docker/Podman execution, Stata execution, and
  publication-ready substantive interpretation.

`rdrobust` and `rddensity` remain optional future upgrades. Their absence cannot
be hidden: this release labels its estimator and limitations explicitly.

## 3. Architecture

The existing `LocalAnalysisSpec` becomes a strict discriminated union with a
shared envelope and three new method-specific authorities. DiD remains backward
compatible.

Shared fields:

- `schema_version`, `method_id`, and absolute `data_path`;
- explicit inference and resource budgets;
- immutable source snapshot reference;
- no undeclared column dropping or data mutation.

Method-specific specs:

1. **Panel FE** declares outcome, regressors, fixed-effect columns, cluster
   column, and confidence level.
2. **IV/2SLS** declares outcome, endogenous regressors, excluded instruments,
   controls, optional fixed effects, cluster column, and a predeclared weak-
   instrument threshold.
3. **RDD** declares outcome, running variable, cutoff, optional controls,
   bandwidth, donut radius, cluster column when applicable, and confidence
   level. Treatment is derived deterministically as `running >= cutoff`.

Each recipe implements the existing registry boundary:

- validate the exact method and snapshotted columns;
- render a repository-owned deterministic R script;
- parse only bounded, exact-schema outputs;
- return one strict result model.

The service and verifier resolve recipes by `method_id`; they do not contain
method-specific estimator logic.

## 4. Estimators and mandatory evidence

### 4.1 Panel FE

The primary estimator uses `fixest::feols` with the declared regressors and fixed
effects. The output must include coefficient estimates, standard errors,
confidence intervals, observation count, unit/time support where declared,
within fit statistics, fixed-effect structure, cluster configuration, and package
versions. Collinearity or an empty estimand fails closed.

### 4.2 IV/2SLS

The primary estimator uses the `fixest` IV formula. The bundle must report:

- structural 2SLS estimate;
- first-stage estimate for every endogenous variable;
- reduced-form estimate;
- excluded-instrument count and exact instrument names;
- first-stage F evidence and the predeclared threshold;
- sample support, fixed effects, clustering, and package versions.

Missing first-stage evidence, under-identification, non-finite estimates, or an
F statistic below the declared threshold produces a scientifically blocked
report rather than a successful causal result. Over-identification evidence is
reported when the declared model makes it available; it is not fabricated.

### 4.3 Local-linear RDD

The RDD recipe fits separate local linear slopes on either side of the cutoff
inside the declared bandwidth, using triangular weights. It reports the cutoff
jump and clustered or heteroskedasticity-robust inference as declared.

Mandatory evidence includes:

- observations and unique running-variable values on each side;
- declared cutoff, bandwidth, kernel, and estimator label;
- main bandwidth estimate plus `0.5x` and `1.5x` bandwidth sensitivity;
- donut estimate using the declared exclusion radius;
- covariate continuity estimates for every declared covariate;
- a binned outcome plot with numeric axes;
- package versions and an explicit statement that robust bias-corrected
  `rdrobust` inference is not part of this release.

The recipe fails closed for one-sided support, insufficient unique running values,
non-positive bandwidth, donut radius outside the bandwidth, empty sensitivity
windows, or non-finite inference.

## 5. Artifacts and verification

Every method publishes the same artifact classes:

1. immutable local-data snapshot;
2. generated R script and reviewed runtime identity;
3. bounded stdout/stderr evidence;
4. method-specific estimate and diagnostic CSV files;
5. deterministic SVG figure with numeric axes;
6. typed result artifact;
7. independently reconstructed verification report;
8. current/history pointers and recovery state.

Verification reopens and hashes the source snapshot, generated script, runtime,
raw output files, parsed result, figure, and exact predecessor chain. A success
boolean supplied by a caller is never authoritative. Any missing, stale,
malformed, or inconsistent method-specific diagnostic blocks PASSED.

## 6. CLI and operator experience

The existing commands remain the user surface:

```text
envresearch econometrics validate --spec SPEC.yaml --run-root RUN_ROOT
envresearch econometrics run --spec-ref REF --run-root RUN_ROOT
envresearch econometrics status --analysis-id ID --run-root RUN_ROOT
```

`validate` returns the method ID, declared estimand columns, snapshot reference,
and whether the already-reviewed local R dependency is available. `run` never
installs a package. `status` returns typed method-specific result and diagnostic
summaries without rerunning the analysis.

## 7. Failure policy

Failures are separated into stable categories:

- invalid specification or incompatible data shape;
- unavailable reviewed local runtime/package;
- estimator failure or non-finite output;
- scientifically blocked diagnostics;
- persistence or verification failure.

Only persistence and explicitly retryable runtime interruptions may resume.
Scientific failures require a revised, newly referenced specification; the
system cannot silently switch methods, bandwidths, instruments, controls, or
samples after observing results.

## 8. Testing and acceptance

Implementation follows RED-GREEN-REFACTOR. Acceptance requires:

- contract tests for all three method-specific schemas and invalid combinations;
- deterministic renderer/parser tests for each recipe;
- adversarial missing/tampered/non-finite diagnostic tests;
- service, recovery, exact-reference CLI, and verification compatibility tests;
- repository-owned synthetic fixtures with known qualitative effects;
- optional real-local-R smoke tests using the installed R 4.4.3 and `fixest
  0.14.0`, without network access or installation;
- unchanged DiD behavior and V0.2 Tier-2 rejection;
- Ruff, format, mypy, lockfile, diff, and changed-file line gates;
- independent code review with no Critical or Important findings.

No external dataset, replication archive, Zotero record, Docker/Podman runtime, or
new R package is required for this release.

## 9. Delivery shape

The implementation plan will use shared tasks rather than one task series per
method:

1. shared discriminated contracts and registry;
2. shared estimate/diagnostic/figure result primitives;
3. Panel FE + IV recipes on the common `fixest` formula layer;
4. local-linear RDD recipe and sensitivity diagnostics;
5. shared service/verifier/CLI integration;
6. real-local-R and compatibility verification, documentation, and review.

This is the smallest coherent bundle that adds all three methods without
rebuilding the Research OS or weakening scientific failure boundaries.
