# V0.3-A: DiD/Event-Study Tier-2 Replication Pilot

## Status and decision

The project owner approved V0.3 after V0.2 human review. This specification
defines only V0.3-A: a controlled DiD/event-study replication pilot. It does
not authorize general data collection, arbitrary package execution, empirical
paper drafting, or automated scientific claims.

The benchmark sequence is deliberately layered:

1. Callaway and Sant'Anna (2021) provides the method contract for staggered
   DiD, group-time ATT, dynamic aggregation, and modern inference.
2. Baker, Callaway, Cunningham, Goodman-Bacon, and Sant'Anna's 2026 JEL
   *Difference-in-Differences Designs: A Practitioner's Guide* materials are
   the first proposed Tier-2 executable benchmark.
3. A separately admitted environmental-policy replication package validates
   the adapter in the target domain after the JEL pilot passes.

## Scope

V0.3-A admits one exact, human-approved Tier-2 package version. The first
runtime profile is R. The adapter contract is language-neutral so that a
separately approved Stata profile can later be added without changing the
artifact schema, approval sequence, or result ledger.

The initial pilot supports only inputs included in the approved archive or
individually declared in its intake manifest. Undeclared secondary downloads,
credentials, interactive logins, and external services are rejected.

### Autonomy policy

V0.3-A follows the Research OS 90/10 operating model: agents advance all
reversible, artifact-backed work by default. They may inspect the approved
package, acquire the approved archive, build the replay workspace, run and
resume the container, compare outputs, create diagnostics, and write the
reproduction report without waiting for routine human confirmation.

Humans decide only irreversible external admission and promotion. An exception
queue, rather than a routine gate, is raised for license ambiguity, undeclared
inputs, integrity failure, unavailable runtime, non-self-contained dependency,
or resource exhaustion.

## Architecture and artifact flow

```text
Package locator
  -> agent intake manifest and license/provenance review
  -> human external-admission approval
  -> acquired archive + immutable file inventory
  -> container preflight
  -> author-workflow reproduction
  -> derived DiD/event-study comparison
  -> result ledger + reproduction report
  -> automatic validation or exception queue
  -> human promotion approval for the next external benchmark
```

The intake manifest records the package DOI or canonical URL, declared
version, license, archive and extracted-file hashes, expected data inputs,
runtime profile, expected outputs, and storage/memory budgets. It also states
whether the package is self-contained. A manifest is immutable after intake
approval; changes create a new review object.

Acquisition is separate from execution. The approved archive is fetched once,
hashed, inventoried, and copied into a dedicated replay workspace. Execution
receives only that workspace, generated runtime configuration, and approved
inputs. It cannot mount the project repository, Zotero library, Obsidian vault,
or ordinary user folders.

## Container runtime

Docker or Podman is mandatory. Absence of an available engine is a hard stop;
there is no unrestricted local fallback.

The execution container must use a pinned image digest, a read-only package
input mount, a write-only output mount, a temporary working directory, and no
network after acquisition. It must run as a non-root user. The runtime record
captures engine version, image digest, R version, installed package lock,
command, environment allowlist, and resource observations.

## DiD/event-study adapter

The adapter separates two outputs.

### Faithful reproduction

The author workflow runs without modification and is evaluated only against
declared original targets: tables, figures, estimates, or intermediate outputs
explicitly mapped in the intake manifest. Tolerances are declared before the
run and become part of the report.

### Derived method comparison

The adapter operates on the approved analysis-ready data without overwriting
author code. It emits a separately labelled diagnostic artifact containing:

- baseline TWFE and event-study specification;
- Callaway-Sant'Anna group-time ATT and dynamic aggregation where the data
  structure supports it;
- treatment-timing, support, balance, and event-time diagnostics;
- estimates, confidence intervals, configuration, and an explanation of any
  estimator differences.

This derived comparison is not represented as a reproduction result or as a
new substantive claim.

## Governance and failure policy

Two human approvals are required:

1. approve the exact package, license, declared inputs, runtime image, and
   resource/storage budget before acquisition;
2. approve admission of the later environmental-policy package after the JEL
   replay has produced a passing, independently verified report.

The reproduction report is not a routine human gate. When its automated
integrity, output-tolerance, and independent-verifier checks are green, the
run completes automatically. Human attention is requested only for an
exception or a promotion decision.

The system fails closed for unclear licenses, missing required documentation,
unexpected files, hash mismatch, unavailable container runtime, undeclared
external access, prohibited host paths, missing result lineage, or output
mismatch outside the declared tolerance.

There is no fixed wall-clock failure threshold. The runner records elapsed
time and durable progress heartbeats. Extended inactivity or unexpected growth
creates a pause-for-review checkpoint. Hard stops apply only to storage or
memory exhaustion, or an explicit operator emergency stop. A paused run can
resume only from its immutable checkpoint and unchanged approved inputs.

## Acceptance criteria

V0.3-A passes only when:

1. the approved container preflight and author workflow complete;
2. declared original outputs reproduce within predeclared tolerances;
3. all archive, input, runtime, command, log, and output hashes are present in
   the result ledger;
4. the derived DiD/event-study comparison and diagnostics are complete;
5. independent artifact verification reports no unresolved finding.

Pilot-8 remains a V0.2 calibration corpus. It cannot be reclassified as a
Tier-2 result or used to bypass the V0.3-A acceptance sequence.

## Testing strategy

Repository tests use only owned fixtures. A dry-intake test validates manifest
and license/provenance handling without acquisition. The first real
package execution is a human-approved run outside CI. Integration tests cover
manifest revision, archive mismatch, blocked paths/network, container
availability, deterministic resumption, result-ledger completeness, output
tolerance comparison, method-comparison labelling, autonomous green-path
completion, and exception-only human escalation.

## Non-goals

V0.3-A does not add paper drafting, external dataset discovery beyond the
approved package, automated publication claims, unrestricted R package
installation, a Stata runtime profile, or a general-purpose code-execution
service.
