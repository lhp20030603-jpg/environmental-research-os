# V0.3 DiD Tier-2 Replication Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a container-only, R-first capability pack that can admit one approved DiD/event-study replication package, reproduce its declared outputs, and create a separately labelled modern DiD comparison with complete artifact lineage.

**Architecture:** Keep V0.2 design fixtures inert and leave the existing trusted local `BenchmarkRunner` unchanged. Add `envresearch.replication` as a separate Tier-2 capability pack: an immutable two-phase intake/acquisition contract, a container executor, a resumable result ledger, and an R DiD adapter. The green path is agent-operated; human input is limited to external admission before download and promotion before admitting a subsequent environmental-policy package.

**Tech Stack:** Python 3.12, Pydantic v2, PyYAML, Typer, pytest, Ruff, mypy, Docker or Podman, R in a digest-pinned container, `did`/`fixest` only inside the approved image.

## Global Constraints

- Preserve V0.2 behavior: `DesignBenchmarkManifest` continues to reject Tier 2 and `executes_replication_package=True`.
- The 90/10 default applies: agents execute every reversible, artifact-backed step; human approval is required only for external admission and later benchmark promotion.
- Do not download, execute, or add the Baker et al. package during repository tests. Tests use repository-owned archives and a fake container engine.
- A Tier-2 input is admitted through a two-phase record: an approved locator before download, followed by an immutable acquired inventory containing the observed archive hash. Do not require a pre-download hash that the host has not published.
- Require Docker or Podman. Do not add an unrestricted local R, Python, shell, or command-runner fallback.
- A running container has no network, runs non-root, mounts package inputs read-only and output only as writable, and never mounts the repository, Zotero library, Obsidian vault, or ordinary user folders.
- Do not impose a fixed wall-clock failure. Persist elapsed time and heartbeats; pause on configured inactivity or unexpected resource growth; hard-stop only storage/memory exhaustion or explicit emergency stop.
- Author reproduction and derived analysis are separate commands and separate labelled artifacts. Derived TWFE/Callaway-Sant'Anna output is never a reproduction result or a substantive paper claim.
- Keep source and test files at or below 400 lines. All public Pydantic models use `extra="forbid"` and frozen instances.
- Use immutable `ResearchArtifact` envelopes and `ArtifactRef` inputs for every approved, acquired, runtime, result, diagnostic, and report artifact.
- The first real package run happens only after the external-admission decision, outside CI. Stata is out of scope; its future profile must implement the same language-neutral contracts.

```python
class ReplicationLedger:
    def heartbeat(self, run_ref: ArtifactRef, observation: ResourceObservation) -> ArtifactRef:
        current = self._require_current(run_ref, {ReplicationRunState.RUNNING})
        return self._supersede(current, heartbeat=observation, state=ReplicationRunState.RUNNING)

    def complete(self, run_ref: ArtifactRef, *, author_outputs: tuple[OutputResult, ...], derived_ref: ArtifactRef) -> ArtifactRef:
        current = self._require_current(run_ref, {ReplicationRunState.RUNNING})
        self._require_declared_outputs(current.payload.approved_intake_ref, author_outputs)
        return self._supersede(current, author_outputs=author_outputs, derived_ref=derived_ref, state=ReplicationRunState.PASSED)
```

Define `OutputResult` as a frozen model with a declared relative output path,
observed SHA-256, comparator, tolerance result, and `ArtifactRef`; define
`ResourceObservation` with elapsed seconds, storage bytes, memory bytes, and
heartbeat time. `ReplicationLedger.start` returns the current run ref used by
all subsequent calls.

Use `ResearchArtifactStore` for the authoritative records and maintain immutable history just as `ResearchArtifactLifecycle` does. Inactivity or unexpected growth changes state to `PAUSED` with a typed exception record; disk/memory exhaustion changes it to `EXCEPTION`. Elapsed time is recorded but is not by itself a failure condition.

```python
class ReplicationVerifier:
    def verify(self, run_ref: ArtifactRef) -> VerificationReport:
        ledger = self._require_current_ledger(run_ref)
        refs = ledger.payload.required_refs()
        findings = tuple(finding for ref in refs if (finding := self._verify_ref(ref)))
        return VerificationReport(run_ref=run_ref, findings=findings, passed=not findings)


class ReplicationService:
    def run(self, approved_ref: ArtifactRef) -> ReplicationReport:
        acquired_ref = self.intake.acquire(approved_ref, self.intake.locator(approved_ref))
        runtime_ref = self._preflight(approved_ref, acquired_ref)
        run_ref = self.ledger.start(approved_ref, acquired_ref, runtime_ref)
        try:
            author = self._run_author_workflow(run_ref)
            derived = self._run_derived_comparison(run_ref)
            completed = self.ledger.complete(run_ref, author_outputs=author, derived_ref=derived)
            verification = self.verifier.verify(completed)
            return self.ledger.publish_verification(completed, verification)
        except ReplicationFault as error:
            return self.ledger.exception(run_ref, error)
```

Define `ReplicationReport` as the read model for a current sealed ledger and
`ReplicationFault` as the typed base exception carrying a stable code and
evidence tuple. Service methods convert only known boundary failures into this
type; programming errors remain failures during development.

`ReplicationVerifier` reopens every referenced artifact through `ResearchArtifactStore`, rechecks its sealed envelope/current immutable history/hash/producer/input chain, and validates that all declared outputs and comparison entries appear exactly once. It has no write API and cannot promote a report. The service must convert a failed verification into `EXCEPTION`; only a zero-finding verification transitions a completed ledger to `PASSED`.
