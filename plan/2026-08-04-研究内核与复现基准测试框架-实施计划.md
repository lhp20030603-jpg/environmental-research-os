# 研究内核与复现基准测试框架实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建 v0.1 研究内核与复现基准测试框架，使系统可以验证研究清单、执行经过授权的复现命令、保存不可破坏且可恢复的运行状态，并对预期输出生成机器可读的比较报告。

**Architecture:** 使用 Python 包 `envresearch` 实现文件系统优先的研究内核。Pydantic 模型定义稳定制品契约；只追加事件日志和原子写入保证恢复能力；受限命令运行器执行基准复现脚本；比较器和报告器把执行结果转化为结构化 Findings。真实论文复现包位于公共引擎仓库之外，仓库只保存来源、许可证、哈希、适配器和预期输出元数据。

**Tech Stack:** Python 3.11、uv、Pydantic、PyYAML、Hydra/OmegaConf、Typer、Rich、Packaging、pytest、pytest-cov、Ruff、mypy

## Global Constraints

- Python 版本范围固定为 `>=3.11,<3.14`；本机首选 Python 3.11。
- 使用 `uv` 管理依赖并提交 `uv.lock`。
- 包名固定为 `envresearch`，CLI 命令固定为 `envresearch`。
- Python 遵循 PEP 8，所有公共函数和方法必须带类型标注。
- 单个源文件控制在 400 行以内；一个文件只承担一个主要职责。
- 配置使用 Hydra/OmegaConf 组合，边界制品使用 Pydantic 验证。
- 所有时间戳使用带时区的 UTC ISO 8601 格式。
- 所有路径使用 `pathlib.Path`；禁止 `shell=True`，禁止把未验证字符串交给 Shell 解析。
- `raw/` 目录视为不可变；任何运行代码都不得写入该目录。
- 单元测试禁止访问网络；真实复现包获取属于显式、可审计的基准准备步骤。
- 测试覆盖率最低为 80%，并且关键状态转换、路径安全、恢复与自我审批规则必须达到分支覆盖。
- 提交信息遵循 Conventional Commits；允许的主要 scope 为 `workflow`、`config`、`data`、`utils` 和 `test`。
- 每个任务必须先写失败测试、确认失败、实现最小代码、确认通过，再提交。

```python
    hash_mismatch_benchmark: tuple[Path, Path],
    tmp_path: Path,
) -> None:
    manifest_path, case_root = hash_mismatch_benchmark
    report = BenchmarkRunner.default().run_manifest(
        manifest_path,
        case_root,
        tmp_path / "integrity-failure-run",
    )
    findings = [
        finding
        for finding in report.findings
        if finding.code == "SOURCE_HASH_MISMATCH"
    ]

    assert findings
    assert findings[0].severity is FindingSeverity.CRITICAL
```
