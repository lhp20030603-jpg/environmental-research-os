# 环境经济学与政策研究操作系统（Research OS）— 设计规范

**状态：** V1.0 首个 governed-run slice 已实现并通过独立复审；产品仍为 `scientific_release_pending`
**日期：** 2026-08-04  
**目标读者：** 项目负责人、贡献者、研究方法审阅者和 Agent 工作流维护者  
**首期实施范围：** 研究内核与复现基准测试框架（Research Kernel and Replay Benchmark Harness）

## 1. 项目目的

本项目将创建一套开源、持续演进的研究操作系统，用于产出完整的环境经济学和环境政策研究论文。

系统将通过专业化 Agents 自动执行常规研究工作，同时在少数高杠杆决策门（decision gates）保留人类问责。目标是约 90% 的工作由 Agents 执行、10% 的工作由人类审阅。该比例衡量的是工作投入，而非作者责任。

系统不绑定于某一篇毕业论文、某个主题、国家、数据集、计量经济学方法、模型供应商或 Agent 运行时。现有 ETS 毕业论文仅作为本地调试样例。系统的主要性能标准，是一个按照方法分层、由已发表论文及其可依法复用的复现材料构成的基准语料库。

## 2. 产品定义

本产品是：

> 一套模块化、可审计、面向特定领域的研究操作系统。它通过论文原型工作流（paper-archetype playbooks）、方法包（methodology packs）、证据可追溯的 Agents、独立验证和人类审批门，将环境经济学或政策研究简报转化为经过验证的论文和复现包。

系统必须通过文件系统优先协议和供应商适配器，支持 Codex、Claude Code、OpenCode 以及未来的 Agent 运行时。持久状态必须保存在版本化文件中，而不是依赖某个模型的对话历史。

## 3. 项目目标

1. 产出完整的环境经济学与政策研究包，而非零散的论文段落。
2. 根据研究问题、估计目标（estimand）、识别条件和数据选择方法，而不是使用硬编码的偏好方法。
3. 通过版本化插件包支持多种论文原型和方法家族。
4. 让每一项定量主张和基于文献的主张都可追溯到证据。
5. 在尽量少的人工干预下复现表格、图形和正文中的数值结果。
6. 在运行中断或部分失败后安全恢复。
7. 使用公开基准和隐藏基准衡量系统改进。
8. 允许 Agents 提出改进，但必须以基准证据和人类晋级审批为前提。
9. 将开源工作流代码与私有、受限或尚未发表的研究材料分离。

## 4. 非目标

首期实施不会：

- 从一个没有约束的单行主题自动生成全新的论文。
- 一次性实现环境经济学中的所有方法。
- 在没有人类主导授权和治理的情况下收集新的田野、问卷、实验室或行政数据。
- 绕过付费墙、许可证、隐私保护、API 条款或机构审查要求。
- 在没有明确批准的情况下提交论文、联系作者、购买数据或发布研究结果。
- 保证论文达到发表水平，或替代负有责任的领域审查和方法审查。
- 将统计显著性视为成功标准。

## 5. 治理原则

### 5.1 没有制品，就不能交接

每个完成的 Agent 任务都必须输出一个通过 Schema 验证、具有版本和来源记录的制品（artifact）。对话消息可以解释工作，但不是权威研究状态。

### 5.2 没有证据，就不能写作

只有当结果进入结果注册表（results registry）、候选主张进入主张—证据账本（claim-evidence ledger）之后，才能开始验证性写作。

### 5.3 不得自我审批

创建科研制品的 Agent 或模型不能成为该制品的唯一评价者。关键问题必须由独立审阅者或人类审批门关闭。

### 5.4 实证主张只能使用真实数据

不得用生成值静默替代缺失的真实观测。合成数据仅可用于软件测试、以模拟本身为明确研究对象的研究，以及明确标注的方法演示。

### 5.5 零结果和不利结果同样有效

工作流不得仅为获得统计显著性或偏好的政策结论而改变方法、结果变量、样本或解释。

### 5.6 可复现性优先于语言流畅度

正确的数据谱系、可执行分析和主张验证，优先于精美流畅的文字。

### 5.7 受控演进

生产组件不能自行修改或晋级。改进必须作为版本化候选方案提出，在隔离环境中评估，接受独立审阅，并由维护者批准晋级。

## 6. 系统边界

系统包含四个架构层。

### 6.1 稳定的研究内核

研究内核负责：

- 工作流状态与状态转换。
- 类型化制品验证。
- 任务分配与依赖解析。
- 人类审批门。
- 检查点、重试和可恢复执行。
- 来源记录、校验和与只追加事件日志。
- 预算与执行限制。
- 插件包兼容性和版本解析。

研究内核负责协调研究，但不包含任何特定方法的科学逻辑。

### 6.2 可演进的能力包

各类能力包独立进行版本管理：

- `paper` 包定义研究论文原型及其必需制品。
- `method` 包定义估计量、假设、诊断、失败策略和输出。
- `domain` 包定义环境领域概念、本体、数据源和政策背景。
- `connector` 包集成 Zotero、公共 API、数据仓库、统计软件和文件格式。
- `verification` 包定义独立的科学检查和完整性检查。

### 6.3 独立保障层

独立审阅者验证制品，但不得静默覆盖制品。审阅必须生成结构化问题、严重级别、证据和关闭条件。

### 6.4 基准与演进层

基准层评估研究内核、能力包、Agents 和完整工作流，并决定候选变更能否晋级。

## 7. 仓库与发布边界

开源系统与研究制品不应无差别地放在同一个仓库中。

### 7.1 公共引擎仓库

公共引擎仓库包含：

- 研究内核代码和 Schemas。
- Agent 角色定义。
- 可以合法再分发的能力包和连接器。
- 验证逻辑。
- 基准元数据和获得许可的公开测试样例。
- 文档、治理与贡献指南。

### 7.2 研究制品仓库

每个研究项目使用独立的制品工作区或仓库。默认保持私有，其中包含运行清单、下载数据、中间制品、分析输出和论文。只有通过发布审批门后，才可以发布完成脱敏的复现包。

### 7.3 当前毕业论文工作区

当前 ETS 工作区包含个人毕业论文材料，不能被自动视为可公开发布内容。将其作为基准之前，必须单独进行脱敏和许可证审计。学生身份信息、导师信息、受限源数据和不可再分发文档不得进入公共引擎仓库。

## 8. 持久制品模型

下列制品构成最小研究协议。

| 制品 | 用途 | 创建者 | 必需审阅者 |
|---|---|---|---|
| `run-manifest.yaml` | 记录版本、模型、工具、环境、预算和运行身份 | 研究编排器 | 内核验证器 |
| `research-charter.yaml` | 定义主题、范围、贡献目标、伦理和约束 | 研究架构师 | 人类审批门 1 |
| `literature-map.json` | 保存筛选后的文献、关系和覆盖范围 | 文献侦察 Agent | 引文验证器 |
| `evidence-matrix.csv` | 将来源映射到问题、方法、发现和局限 | 证据分析 Agent | 文献审阅者 |
| `data-feasibility.yaml` | 评估数据可得性、访问条件、成本、许可证、单位和覆盖范围 | 数据侦察 Agent | 数据管理员 |
| `data-provenance.yaml` | 记录来源、获取、转换、哈希和许可证 | 数据工程 Agent | 完整性审计员 |
| `estimand-spec.yaml` | 定义总体、处理或暴露、结果、对比和时间 | 方法学 Agent | 研究设计批评者 |
| `identification-memo.md` | 论证识别策略并回应替代解释 | 方法学 Agent | 计量经济学审稿人 |
| `analysis-plan.yaml` | 预注册主要结果、模型设定、排除规则和后备方案 | 研究设计团队 | 人类审批门 3 |
| `results-registry.json` | 保存模型输出、不确定性、诊断和输出谱系 | 分析 Agent | 复现验证器 |
| `claim-evidence-ledger.json` | 将论文中的每项主张连接到来源或注册结果 | 证据综合 Agent | 主张审计员 |
| `argument-map.json` | 定义论文论证逻辑和章节依赖 | 论文架构 Agent | 领域审阅者 |
| `review-findings.json` | 记录结构化问题、严重级别、证据和关闭状态 | 审阅 Agents | 修订整合 Agent |
| `response-matrix.md` | 将审阅问题映射到修订及仍存分歧 | 修订整合 Agent | 审稿人小组 |
| `release-manifest.yaml` | 认证已批准制品及公开发布状态 | 研究编排器 | 人类审批门 5 |

Schemas 是稳定接口。在保持 Schema 兼容性的前提下，制品内容可以演进而不破坏使用方。

## 9. Agent 拓扑

### 9.1 控制平面

研究编排器（Research Orchestrator）读取工作流状态、分配边界明确的任务、执行审批门、记录谱系并处理重试。它不能虚构科学结果、选择偏好的发现，或审批自己的工作。

### 9.2 发现阶段生产者

- 文献侦察 Agent（Literature Scout）
- 政策映射 Agent（Policy Mapper）
- 数据侦察 Agent（Data Scout）
- 创新性分析 Agent（Novelty Analyst）

它们负责生成研究章程输入、文献地图、证据矩阵和可行性报告。

### 9.3 设计阶段生产者

- 领域经济学 Agent（Domain Economist）
- 方法学 Agent（Methodologist）
- 数据管理员（Data Steward）
- 统计功效与可行性分析 Agent（Power and Feasibility Analyst）

它们负责生成估计目标规范、识别备忘录、数据计划、适用情况下的统计功效评估，以及预注册分析计划。

### 9.4 执行阶段生产者

- 数据工程 Agent（Data Engineer）
- 方法包分析 Agent（Method-Pack Analyst）
- 可视化 Agent（Visualization Agent）

它们负责创建通过验证的数据清单、可执行分析、注册结果、表格和图形。

### 9.5 综合阶段生产者

- 证据综合 Agent（Evidence Synthesizer）
- 论文架构 Agent（Paper Architect）
- 章节起草 Agents（Section Drafters）
- 修订整合 Agent（Revision Integrator）

它们负责构建主张账本、论证地图、论文、披露日志和审阅回复。章节起草 Agents 只能依据已批准的制品写作。

### 9.6 独立审阅者

- 复现审计员（Replication Auditor）
- 计量经济学审稿人（Econometrics Referee）
- 领域审稿人（Domain Referee）
- 引文验证器（Citation Verifier）
- 图表审阅者（Exhibit Reviewer）
- 文本审阅者（Prose Reviewer）
- 完整性审计员（Integrity Auditor）
- 政策主张审计员（Policy-Claim Auditor）

审阅意见不得静默修改生产者制品。修订必须生成新的制品版本，并保留被审阅的旧版本。

## 10. 端到端工作流

### 阶段 1：发现（Discover）

1. 规范化研究简报。
2. 通过 Zotero 和权威来源搜索、导入和筛选文献。
3. 构建文献地图和证据矩阵。
4. 识别候选研究问题和潜在贡献。
5. 在确定研究问题前审计数据可行性。

**人类审批门 1：** 批准研究章程、伦理边界和预期贡献。

### 阶段 2：设计（Design）

1. 定义估计目标和目标总体。
2. 审计分配机制、变异、时间结构和数据结构。
3. 筛选论文原型和方法包候选名单。
4. 比较识别可信度和替代方案。
5. 预注册主要结果、模型设定、排除规则和后备规则。

**人类审批门 2：** 批准受限数据访问、许可证、隐私条件或实质性获取成本。  
**人类审批门 3：** 批准识别策略和分析计划。

### 阶段 3：执行（Execute）

1. 获取公共数据或已批准数据，并验证哈希。
2. 通过可执行且有日志记录的流水线转换数据。
3. 运行预注册的主要分析。
4. 运行强制诊断和已声明的稳健性检验。
5. 注册每一项将被报告的结果和图表。
6. 在独立验证环境中复现结果。

科学性失败必须返回设计审批门，不得触发自动方法搜索。

### 阶段 4：综合（Synthesize）

1. 构建主张—证据账本。
2. 构建论证地图和章节提纲。
3. 根据已批准证据起草章节。
4. 审计引文、数值一致性、因果语言、图形、表格和文本。

**人类审批门 4：** 审阅实质性机制、政策含义、局限和不确定性。

### 阶段 5：保障与发布（Assure and Release）

1. 进行独立复现、计量经济学、领域和完整性审阅。
2. 按照结构化回复矩阵修订。
3. 修订后重新运行完整复现包。
4. 生成论文、附录、代码、数据声明和复现包。

**人类审批门 5：** 接受作者责任并批准对外发布。

## 11. 论文原型

系统将通过独立论文包支持以下原型：

1. 因果政策评估。
2. 实验与行为环境经济学。
3. 环境价值评估与成本—收益分析。
4. 空间与时间维度的环境分析。
5. 结构性政策建模与模拟。
6. 环境测量与核算。
7. 系统综述、Meta-analysis 和政策证据综合。

每个论文包必须声明必需制品、允许的主张类型、最低稳健性标准和预期论文章节。论文包可以与方法包组合，但不实现估计量。

## 12. 方法包契约

每个可执行方法包必须声明：

1. 支持的研究问题和估计目标。
2. 所需观察单位、样本结构、时间结构、分配机制和变异。
3. 识别假设或建模假设。
4. 强制诊断和警告阈值。
5. 主要估计量、已声明替代方案和敏感性分析程序。
6. 必需表格、图形和注册统计量。
7. 失败条件和允许的响应。
8. 解释边界，包括允许使用的因果语言。
9. 权威方法学参考文献。
10. 软件环境和依赖锁定文件。
11. 基准案例和预置失败测试。
12. 方法包版本以及与内核和 Schema 的兼容性。

## 13. 方法家族与扩展顺序

### 第一波：多样化实证核心

- RCT 分析。
- DiD 与 event study。
- Regression discontinuity。
- Instrumental variables。
- Synthetic control。
- 描述性环境测量。
- 系统综述与 Meta-analysis。

### 第二波：价值评估与时空方法

- Hedonic pricing。
- Discrete choice experiments。
- Contingent valuation。
- Travel-cost models。
- Spatial econometrics。
- Exposure models。
- 环境时间序列与预测。

### 第三波：结构模型与模拟方法

- Structural demand and supply。
- Partial-equilibrium models。
- Computable general equilibrium（CGE）models。
- Integrated assessment models（IAM）。

结构模型带来额外验证要求，因此第三波必须在建立更强的校准、求解器验证和敏感性分析基础设施后实施。

## 14. 方法选择保障机制

方法选择必须发生在查看验证性结果之前。

1. 定义估计目标。
2. 审计数据结构和识别变异。
3. 生成兼容方法包候选名单。
4. 对识别适配度、数据可行性、假设可信度和政策可解释性进行评分。
5. 运行独立的对抗性研究设计审阅。
6. 选择主要方法并声明后备方案。
7. 锁定分析计划。

禁止以下行为：

- 仅因存在看似兼容的数据，就默认使用熟悉的方法。
- 反复尝试不同方法，直到某个方法跨过显著性阈值。
- 在没有日志化规则的情况下删除结果变量、观测、时期或单位。
- 将任意替代模型设定包装为稳健性检验。
- 对只能识别相关关系的研究设计使用因果语言。
- 隐瞒对预注册计划的偏离。

当假设不成立时，系统必须生成科学性失败问题。系统可以使用预注册后备方案，或返回人类审批门 3。任何查看结果后的研究设计变更都必须保留在偏离日志中。

## 15. 基准语料库

基准必须是分层语料库，而不是一篇示范论文。案例应覆盖：

- 论文原型。
- 方法家族。
- 环境主题。
- 地理和制度背景。
- 数据类型和访问条件。
- 软件环境。
- 计算复杂度。
- 正向、零、混合以及假设失败的研究结果。

主要来源包括 AEA Data and Code Repository 等可信仓库中的已发表论文复现包。语料库可以使用 APE 的人类论文基准名单发现候选论文，但原始期刊论文和获得授权的复现存档才是权威制品。

当前 ETS 毕业论文在脱敏后可作为 Tier 1 调试样例，但不能作为方法选择或写作风格的规范模板。

## 16. 基准层级

### Tier 0：软件检查

测试 Schemas、解析器、状态转换、失败处理器和确定性工具。由于不会产生实证研究主张，因此允许使用合成测试样例。

### Tier 1：已知复现

系统可以看到完整研究和复现制品，并必须重新运行、提取和比较输出。

### Tier 2：遮蔽式重建

隐藏已发表研究发现。系统获得允许使用的源材料，并必须重建研究设计、分析和图表。

### Tier 3：跨论文迁移

系统获得新的问题或数据集，并必须迁移合适的研究逻辑，而不是复制基准模板。

### Tier 4：盲测研究

系统处理全新的研究简报。在发布前，由人类专家和独立模型评估研究设计、证据、论文和复现包。

## 17. 评价指标

### 科学有效性

- 识别质量。
- 假设处理。
- 估计目标一致性。
- 不确定性校准。
- 政策主张克制程度。
- 发现预置科学性失败的能力。

### 可复现性

- 流水线完成率。
- 表格、图形和数值结果在声明容差范围内的一致性。
- 确定性重新运行成功率。
- 环境重建成功率。
- 中断后恢复能力。

### 证据完整性

- 引文验证率。
- 主张—证据覆盖率。
- 数值一致性。
- 无证据主张和幻觉率。
- 数据与代码来源记录完整度。

### 运行效率

- 人工干预时间。
- 计算与模型成本。
- 端到端运行时间。
- 重试和恢复率。
- 冗余或不必要的 Agent 调用。

## 18. 持续演进治理

1. 基准或生产失败创建一个结构化 Issue。
2. Agent 或贡献者在隔离分支上提出候选变更。
3. 候选变更在公开回归案例和隐藏留出集上接受评估。
4. 独立审阅者评估科学与工程回归。
5. 维护者批准或拒绝晋级。
6. 发布记录分数变化、兼容性、模型配置和已知局限。

候选方案必须改善目标指标、通过全部关键安全阈值，并且不得在其他方法家族或论文原型上引入实质性退化。

防止基准过拟合的措施包括隐藏留出集、定期轮换新论文、遮蔽研究结论、迁移案例、在可行情况下分离基准作者和能力包维护者，以及对高层次判断进行跨模型评价。

## 19. 失败处理与恢复

### 瞬时失败

示例：API 超时、速率限制、临时服务错误、模型调用中断。  
响应：采用有限次数的指数退避重试，并记录事件。

### 可恢复的技术失败

示例：Schema 不匹配、制品格式错误、缺失依赖、下载不完整。  
响应：创建边界明确的修复任务，重新验证，并从最后一个有效检查点恢复。

### 科学性失败

示例：识别薄弱、假设不成立、统计功效不足、变异不可用、证据不一致。  
响应：停止受影响阶段，并携带结构化问题返回研究设计审批门。

### 完整性或安全失败

示例：伪造数据、无法核验的引文、隐私泄露、许可证违规、隐瞒操纵。  
响应：立即硬停止并交由人类审阅，禁止自动继续。

### 资源失败

示例：计算预算耗尽、运行时间过长、必需服务不可用。  
响应：保存运行检查点，报告剩余需求，只有在资源或范围改变后才能恢复。

在可行情况下，任务必须具有幂等性。制品写入必须具备原子性、校验和，并保留版本。工作流状态必须明确：`pending`、`running`、`passed`、`failed`、`repair_pending`、`review_required`、`approved`、`rejected` 和 `superseded`。

## 20. 安全与授权边界

在已批准的研究运行范围内，Agents 可以自动执行以下可逆工作：

- 搜索和整理带有来源记录的文献。
- 按许可条款获取公共数据。
- 按照已批准规范清理数据。
- 运行预注册模型、诊断和稳健性检验。
- 根据已验证证据起草文本。
- 根据有日志记录的审阅意见修订。

Agents 执行以下操作需要明确批准：

- 购买、许可、披露或再分发受限数据。
- 在查看结果后改变主要估计目标。
- 使用合成值替代缺失的实证观测。
- 提出超出已批准研究设计的因果或政策主张。
- 提交、发布、联系第三方或建立外部承诺。

Secrets 必须保存在仓库和研究制品之外。运行记录应保存软件版本，但不得记录访问令牌。公开发布前必须自动检查密钥、个人信息、许可证和受限数据。

## 21. 版本化谱系

每次运行必须记录：

- 研究内核和制品 Schema 版本。
- Agent 角色和 Prompt 版本。
- 模型供应商、模型标识符和推理配置。
- 工具和连接器版本。
- 论文包、方法包、领域包和验证包版本。
- 数据集快照、哈希、来源记录和许可证元数据。
- 环境锁定文件和相关系统依赖。
- 随机行为影响结果时所使用的随机种子。
- 基准快照和评价量表版本。

## 22. 技术方向

实现将使用：

- 由 `uv` 管理的 Python。
- Hydra 和 OmegaConf，用于可组合、类型化配置。
- Pydantic 或 JSON Schema，用于制品验证。
- 文件系统优先协议，使研究运行可以在不同 Agent 运行时之间移植。
- Git，用于代码、Prompt、Schema 和已批准制品的版本管理。
- 供应商适配器，而不是硬编码依赖某一个 LLM。
- 当方法包或基准需要时使用 R、Python、Stata 或其他统计运行时；研究内核在任务边界保持语言中立。

初始界面为 CLI 和版本化制品树。图形化 Dashboard 推迟到工作流和 Schemas 稳定之后。

## 24. 发布路线图

### v0.1 — 复现基础（Replay Foundation）

- 研究内核和制品 Schemas。
- 检查点、审批门和审计谱系。
- 基准注册表和复现包运行器。
- 当前 ETS 调试样例与获得许可的开放复现包。

**退出标准：** 复现至少三个方法家族的研究包，验证所有必需谱系，并能从强制中断中完整恢复。

### v0.2 — 研究设计引擎（Research Design Engine）

- Zotero 与文献证据工作流。
- 研究章程和创新性地图。
- 公共数据可行性审计。
- 方法候选、批评和预注册。

**退出标准：** 独立专家认为系统在遮蔽式基准问题上的方法建议可信，且已接受制品中不存在未经验证的引文。

### v0.3 — 证据运行器（Evidence Runner）

- 数据获取和清理契约。
- 可执行的第一波方法包。
- 诊断、稳健性检验和结果注册表。
- 独立复现验证器。

**退出标准：** 在声明容差内重建被遮蔽的结果，并发现预置的假设失败或完整性失败。

### v0.4 — 论文构建器（Paper Builder）

- 主张—证据账本和论证地图。
- 根据已验证制品进行完整章节写作。
- 引文、图表、文本和政策主张审计。
- 审稿和修订循环。

**退出标准：** 生成不存在已接受但无证据支持的主张、且所有图表可复现的基准论文。

### v1.0 — 研究工厂（Research Factory）

- 跨已批准审批门的端到端编排。
- 隐藏留出集和持续评价。
- 由基准控制的能力包演进。
- 可发布的论文和复现包。

**退出标准：** 在支持的论文原型上，常规工作达到 90/10 人类投入目标，并且隐藏测试套件中没有关键完整性失败。

**当前实现边界（2026-08-20）：** 首个 slice 已将 exact V0.2
approved design 与 exact current V0.4 release 组装为可独立重开的
`ResearchFactoryRun`，并实现 independent human 的 individual-run
promotion。最终 post-fix 门禁为 unit 1,440 passed，integration
1,264 passed / 39 expected skips，combined coverage 2,704 passed / 39
expected skips，58,955 statements / 3,989 missed = 93.233822%；scoped
pre-document review 为 0 Critical / 0 Important / 0 Minor，最终文档
复审仍待完成。由于
`ENVRESEARCH_V04_ACCEPTANCE_ROOT` 未提供，formal sealed-root 用例仍为
honest skip，不记为通过。

该 promotion 仅适用于一个 exact retrospective-coherence run，不是
V1.0 产品级 scientific promotion。下一 slice 固定为 hidden evaluation、
benchmark-controlled capability-pack evolution 和 replication-package
evaluation；三者完成前产品继续保持 `scientific_release_pending`。

## 25. 首个实施子项目

首个实施计划必须只覆盖 **研究内核与复现基准测试框架（Research Kernel and Replay Benchmark Harness）**。

### 范围内

- 运行清单和最小制品 Schemas。
- 工作流状态机。
- 人类审批门接口。
- 原子化制品、校验和、检查点与可恢复执行。
- 能力包清单与兼容性验证。
- 基准注册表。
- 一个用于执行获准复现脚本的语言中立命令运行器。
- 使用可配置数值和文件容差进行输出比较。
- 结构化问题与机器可读运行报告。
- 强制中断测试和预置失败测试。
- 一个规模较小、获得许可且覆盖至少三个方法家族的初始基准集。

### 范围外

- 自动文献搜索。
- 生成全新的研究问题。
- 获取新数据。
- 自动方法选择。
- 实现新的计量经济学估计量。
- 生成论文。
- 自我改进组件的生产晋级。

首个子项目用于证明后续 Agents 所依赖的契约、可审计性、恢复机制和衡量基础。

## 26. 首个子项目验收标准

1. 可以根据基准清单初始化一次新运行。
2. 无效清单和制品必须在执行前失败，并给出可操作的问题说明。
3. 每次任务状态转换都记录在只追加事件日志中。
4. 被强制终止的运行可以从最后一个有效检查点恢复，且不会破坏已有制品。
5. 对同一基准重新运行时，在声明容差内得到相同的注册输出。
6. 公开基准包保留来源、DOI、版本、许可证和校验和元数据。
7. 基准比较报告必须区分匹配、不匹配、缺失和意外输出。
8. 能够发现预置的 Schema、执行、科学元数据和完整性失败。
9. 引擎绝不写入不可变的原始来源目录。
10. 任何模型或 Agent 都不能将自己发现的关键问题标记为已解决。

## 27. 主要风险与缓解措施

| 风险 | 缓解措施 |
|---|---|
| 方法或基准过拟合 | 隐藏留出集、迁移任务、轮换案例和遮蔽结论 |
| 文字流畅但缺乏证据 | 主张—证据账本和“无证据不写作”审批门 |
| 自动化 p-hacking | 查看结果前的方法选择、预注册分析计划和偏离日志 |
| 单模型盲点 | 独立审阅者角色，以及在有价值时采用跨模型评价 |
| Agent 行为不可复现 | 对 Prompt、模型、工具、Schemas、数据哈希和环境进行版本管理 |
| 运行中断或部分损坏 | 原子写入、校验和、幂等任务和检查点 |
| 受限数据泄露 | 独立私有制品工作区，以及发布时的许可证与隐私扫描 |
| 范围过大 | 发布审批门和边界狭窄的首个子项目 |
| 自动化成本过高 | 每份基准报告记录成本和人工耗时指标 |
| 自我改进导致回归 | 候选分支、隐藏基准、独立审阅和维护者晋级 |

## 28. 已批准的设计决策

1. 使用研究操作系统架构，而不是仅包含方法的工具箱或相互重复的独立流水线。
2. 保持研究内核稳定且与具体方法无关。
3. 使用类型化、版本化制品表示研究状态。
4. 分离生产者和审阅者责任。
5. 使用通用方法包契约和预注册方法选择流程。
6. 使用分层基准语料库，而不是一篇示范论文。
7. 将当前毕业论文作为调试样例，而不是规范模板。
8. 使用基准和人类晋级审批控制持续演进。
9. 使用五个人类审批门，分别负责研究问题、数据授权、研究设计、结果解释和发布。
10. 从研究内核与复现基准测试框架开始实施。
